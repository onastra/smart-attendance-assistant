## 补遗（11-03）：免费版 SDK 自带 RGB 活体，已开启（0870010）
- 实测结论：ArcFace V3.0 免费人脸识别 SDK **内置单目 RGB 活体**，无需另找「单目RGB活体检测SDK」（那只是独立精简版）。验证路径：init(supportLiveness=true)=0 → detectFaces → process(ex, faces, func只开Liveness) → getLiveness → isAlive=1。注意 86019=FEATURE_UNPROCESSED 表示漏了 process 步骤。
- V3.0 API 与 V4.0 不同：Builder 方法不带 set 前缀（.detectFaceMaxNum(3)）；detectFaces 用 ImageInfoEx（planes+strides）而非 ImageInfo。
- 服务改动：extractFeature 内质量校验后追加 assertAlive；策略=仅 isAlive==0 明确假体才拒绝，-1 不确定放行防真人误伤；配置 lz.face.liveness-enabled 默认 true。
- 数字降级图（缩小放大+模糊+降饱和）不是有效假体样本，活体照样判真人——RGB 活体识别的是物理翻拍的摩尔纹/反光。答辩演示建议：手机翻拍电脑屏幕上的人像照片再上传，应被拒。
- 实测回归：enroll/verify 全通过，similarity=1.0，status available=true。

## 补遗（11-03）：刷脸打卡完整链路落地（a37c55d，已推送）
- 定位：三维校验模型——时间(二维码+全局配置)/位置(围栏)/身份(人脸活体+1:1)。人脸是与扫码并列的第三通道，非替代。
- 后端：FaceCheckinController 放 lz-app（face 与 attendance 模块不互相依赖，编排层放应用层）。流程=faceService.verify(token本人)→通过后 checkinService.faceCheckin 落库 source=FACE，remark 记相似度。checkinType 仅 AUTO/ON_DUTY/OFF_DUTY（外勤必须管理员签二维码，防自选规避迟到判定——与扫码通道原则一致）。
- 踩坑：resolveResult 无 AUTO 分支，AUTO 直接判定会被当下班（上午打卡判"早退"）。扫码通道是先 autoCheckinType 换算再判定的；人脸通道修复为同样先换算。
- 防重跨通道：新增 countRecentAnyPlace（同员工同类型跨场所跨通道），扫过上班卡 5 分钟内刷脸再打也会拦。
- 小程序：pages/face-checkin，wx.chooseMedia 拍照（camera:front）→ wx.uploadFile multipart；未注册时同照片先 enroll 再自动继续打卡；结果复用 checkin-result 页。
- 管理端：FaceEnrollList.vue（/api/face/features 名单+删除=disable 停用）；菜单"人脸打卡（模拟）"已改名"人脸核验（体验）"。
- E2E 6 项：本人 AUTO→ON_DUTY/LATE✓、跨通道防重✓、他人照片 0.4297 拒✓、FIELD 拒✓、未注册提示✓、流水 remark 含相似度✓。修复前的脏测试记录已从共享库清除。
- 注意：miniprogram/config.js BASE_URL 指向阿里云 FC 线上后端——本地测试刷脸需把新 jar 部署上去或临时切本机地址。
