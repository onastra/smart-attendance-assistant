### 手机端演示链路（H5 打卡 + 小程序真机扫码）实测结论

**本机局域网 IP：192.168.1.4（WLAN）**。另有 VMware(192.168.121.1/192.168.47.1)、WSL(172.29.176.1) 网段，
演示时手机必须和电脑在**同一个 Wi-Fi**，别用错 IP。

**已实测通过（2026-10-27 20:16）**：
- Vite 5.4.21（含 `allowedHosts` 安全限制的版本）配了 `host: '0.0.0.0'`，
  用局域网 IP 访问 `http://192.168.1.4:5173/h5/checkin` 返回 **200，未被 allowedHosts 拦**
  （Vite 默认放行 IP 形式的 Host，只拦未知域名）
- 后端 Spring Boot 默认绑 **0.0.0.0:8080**（application.yml 未设 server.address），局域网 IP 直连 health 正常
- H5 页的 `/api` 经 Vite 代理从局域网 IP 访问也通 → **手机只需能到 5173**，不用放行 8080
- Windows 防火墙：20 条 java/node 入站 Allow 规则**全部在 Public 配置且 Enabled**，手机可达

**核心结论：H5 在手机上无法真扫码**。局域网 HTTP 不是 secure context，
浏览器禁止 getUserMedia/geolocation。`Checkin.vue` 已写好降级：
`isSecure = window.isSecureContext`，点扫码会提示"当前地址不是 HTTPS 或 localhost…请用手动输入"。**这是浏览器策略不是 bug**。
- 变通①（零改动）：后台「考勤二维码」页有 **「复制原文」** 按钮 + `openH5`，复制原文发到手机粘贴提交，
  完整校验链照走（签名/有效期/场所/绑定/幂等/围栏），仅跳过围栏校验
- 变通②（Android）：chrome://flags 开 `#unsafely-treat-insecure-origin-as-secure` 填该 http 源
- 变通③：给 Vite 加 HTTPS（mkcert 或 @vitejs/plugin-basic-ssl）→ 手机访问 https 并接受证书警告
- 变通④：内网穿透（cpolar/natapp/frp）拿 HTTPS 公网地址

**小程序真机扫码要点**：
- `wx.scanCode` **模拟器不能真扫**（只弹"选本地图片"），必须真机预览/真机调试；
  但模拟器用"选图片"可验证扫码之后的全部业务逻辑
- 小程序**没有 Vite 代理**，`config.js` 的 BASE_URL 必须直连后端：`http://192.168.1.4:8080`
- 必须勾「详情 → 本地设置 → 不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」
- `app.json` 已声明 `permission.scope.userLocation` 与 `requiredPrivateInfos: ["getLocation"]` ✓
- 演示用**长期固定码（24 小时）**：动态码默认仅 120 秒（`LZ_QR_DYNAMIC_TTL:120`，固定码 86400），
  扫码演示中途会过期；且**别勾「一次性」**（onceOnly=1 时第二次扫就失败）
- 校园网/企业 Wi-Fi 可能有 AP 隔离 → 手机连不上电脑时改让电脑连手机热点
