### 修编辑员工改工号不生效（提交 7dd9f60）

**现象**：编辑员工 LZ0007→LZ0008，提示"更新成功"，但列表和 Supabase 库里都是旧值。

**根因**：`EmployeeMapper.xml` 的 `updateById` 动态 set **漏了 emp_no 列**——
Service 层专门写了工号唯一性校验（countByEmpNo+excludeId），说明本意支持改工号，
是 SQL 漏字段静默丢弃修改。返回 R.ok() 所以前端显示成功，最难察觉的一类 bug。

**连带修掉更危险的隐患**：前端 openEdit 把 empNo 重置为 ''（占位文案"留空表示不修改"），
而 MyBatis `<if test="empNo != null">` 对空串也成立 → **留空提交会把 emp_no 清空成 ''**。
修法：Mapper 条件改 `empNo != null and empNo != ''`；openEdit 回填 row.empNo。

**数据安全性确认**：emp_no 仅 hr_employee 一表（唯一索引 uk_emp_no），考勤等表以
employee_id 关联 → 改工号不影响历史数据，可以放心开放编辑。

**验证**（local,cloud 连 Supabase）：PUT id=7 empNo=LZ0008 → code=0；接口回读 LZ0008；
psql 直查 DB emp_no='LZ0008'；反面验证 empNo 留空提交后 emp_no 仍为 LZ0008 未被清空。
用户想改的 LZ0008 已顺带生效（李四 id=7）。

**排查手法**：MyBatis 动态 SQL "更新成功但没生效"先查 XML 的 <set> 里有没有那一列——
实体有字段、Controller/Service 链路正常不代表 SQL 会更新它。
