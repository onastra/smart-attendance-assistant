### Supabase 共享数据库支持（提交 691c1c7）

用户需求：与合作用共用一个 Supabase，代码拉取后双方数据互通。

**关键发现：schema.sql 头部就写着「PostgreSQL 15+（Supabase 实测 PG 17）」**——
合作用做 PG 迁移时已在 Supabase 上验证过建表脚本；pg_trgm 是 Supabase 内置扩展；
种子/回归脚本的 LZ_PG_SSLMODE 默认 require。**兼容性零改动，只差连接配置。**

实现（cloud profile 方案，不动 local）：
- `application-cloud.yml.example` 新模板：cloud 覆盖数据源（Supabase Session pooler +
  sslmode=require）+ 两个**必须两机一致**的共享密钥（lz.security.jwt.secret、
  lz.attendance.qr-sign-secret）
- 启动：`--spring.profiles.active=local,cloud`（later profile 覆盖 earlier，
  Redis/LLM/地图 Key 仍用各自 local）；去掉 `,cloud` 即切回本机 Docker 库
- `.gitignore` 加 application-cloud.yml；docs/shared-supabase.md 七节完整指引
- 本机 tasks.json（gitignore）加了「dev: 后端（云端库 Supabase）」任务

**两个跨机密钥坑（为什么必须共享密钥）**：
1. JWT secret 不同 → A 签发的登录 token 在 B 后端直接 401
2. qr-sign-secret 不同 → A 后台签发的场所二维码在 B 后端被 HMAC 校验判"伪造"
（真实场景：管理后台在 A 机生成码，员工手机 BASE_URL 指向 B 机）

**连接串要点**：必须用 Session pooler（aws-0-<region>.pooler.supabase.com:5432，IPv4）；
db.<ref>.supabase.co 免费版 IPv6-only 连不上；Transaction pooler 6543 不支持
JDBC 会话语义。用户名带项目前缀 `postgres.<ref>`。

**双缓存注意**：两后端各连本机 Redis，A 写库不会失效 B 的缓存，等 TTL
（统计 60s / 场所详情 600s）。免费版 7 天不活跃自动暂停，答辩前要 Restore。

**初始化警示**：schema.sql 含 DROP TABLE IF EXISTS，只能由一人执行一次，
另一人再跑会清空全部数据（文档里加粗强调）。
