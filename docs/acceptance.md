# 项目验收清单与演示脚本

> 本文所有"实测结果"均来自真实执行（`npm run verify` 全量回归），不是计划值。
> 回归入口：`npm run verify`（含 Maven 单元测试 + 四套接口回归，共 **192 项**）。
> 最后更新：2026-10-26

---

## 0. 一句话概括

一个**模块化单体**的毕业生实习考勤管理系统：服务端签发带签名的考勤二维码，员工用手机 H5 扫码或人脸核验打卡，
数据落到 MySQL 后由定时任务幂等重算日汇总，管理员在 ECharts 看板上看趋势与部门对比，另有基于 MySQL 全文检索的知识库问答。

**系统边界说清楚的部分**（答辩必须主动讲，不要藏着）：
- 人脸识别是**明确标注的模拟适配层**（`mock=true`），不是真的人脸识别；考勤以二维码为准
- AI 问答在无大模型 Key 时降级为 **retrieval-only**（只给原文依据，不生成、不编造）
- 地图服务未接入，坐标手动录入，接口如实上报 `enabled=false`

## 2. 十分钟演示脚本

### 前置准备（演示前做完，不计入 10 分钟）

```bash
# 1. 后端（8080）与前端（5173）已在运行
# 2. 本机 MySQL / Redis 已启动
# 3. 演示账号
#    admin     / Admin@123   管理员（全量）
#    manager01 / Admin@123   部门主管（本部门）
#    emp01     / Emp@123     普通员工（仅本人）
# 4. 若刚重建过数据库，先重算一次日汇总
curl -X POST http://localhost:8080/api/statistics/daily-rebuild \
  -H "Authorization: Bearer $(curl -s -X POST http://localhost:8080/api/auth/login \
     -H 'Content-Type: application/json' -d '{"username":"admin","password":"Admin@123"}' \
     | node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>console.log(JSON.parse(s).data.token))")"
```

> 浏览器建议开两个标签：一个后台管理（`/`），一个 H5 打卡页（`/h5/checkin`）。

## 3. 演示时的三个"主动交代"

这三件事不要等老师问，主动说，反而加分：

1. **为什么是单体而不是微服务**
   —— 已按模块化拆分（11 个 Maven 模块），Nacos/微服务是"已配置未启用"；
   在这个体量下微服务带来的是运维复杂度而非收益，但模块边界已按未来可拆分的方式划定。

2. **人脸识别为什么是模拟**
   —— 虹软 SDK 需要商业授权和产品密钥，课程周期内拿不到；
   因此做了可插拔的接口 + 明确标注的模拟实现，真实 SDK 的接入清单写在 `docs/face-sdk-integration.md`。
   **考勤以二维码为准**，人脸只是核验通道。

3. **AI 为什么只检索不生成**
   —— 没有可用的大模型 Key；有 Key 时 `LlmClient` 会自动切换到 OpenAI 兼容实现，
   但"检索无命中就返回未找到"这条底线不会变，绝不让它编造制度的条款。

## 4. 演示失败时的应对

| 现象 | 处理 |
|---|---|
| 页面空白 / 接口 500 | 后端可能未启动或端口被占；看 `/api/system/health` |
| 打卡提示"重复打卡" | 5 分钟去重窗口，换员工或等窗口过去（或用一次性码） |
| 知识库检索不到刚上传的文档 | MySQL 5.7 的 InnoDB 全文索引对刚插入的行有极短缓存合并时延，**等 1~2 秒重试**即可 |
| 看板全 0 | 日汇总没算：调用一次 `/api/statistics/daily-rebuild`（不带参数会自动推导区间） |
| 二维码扫不出 | 直接用页面上的"复制原文"粘贴到 H5 页的手动输入框 |
