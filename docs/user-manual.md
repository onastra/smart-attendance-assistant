# 用户手册

> 面向最终使用者（管理员 / 部门主管 / 普通员工）。开发与部署请看 `deployment.md`。
> 最后更新：2026-10-26

---

## 1. 登录与角色

打开系统首页，用账号登录。不同角色看到的菜单不同——这是由后端权限控制的，
菜单不是写死在前端的。

| 角色 | 示例账号（演示口令） | 能看到的范围 |
|---|---|---|
| 系统管理员 | `admin` / `Admin@123` | 全部数据 + 全部功能 |
| 部门主管 | `manager01` / `Admin@123` | 本部门员工、本部门统计；无账号/角色管理权限 |
| 普通员工 | `emp01` ~ `emp03` / `Emp@123` | 仅本人考勤；可参与知识库问答 |

> 演示环境口令仅用于本机演示。正式部署必须由管理员首次登录后强制修改。

登录后先看左侧「**系统与依赖状态**」页：它如实列出 Redis、人脸、地图、大模型等外部能力的启用情况。
**没接入的会明确写"未启用"，这是刻意的**——避免把没做的事伪装成已做完。

## 2. 管理员操作指南

### 2.1 建立组织架构

菜单：「组织架构」

1. 先在**公司**页签新建公司；
2. 再到**部门**页签建部门（选择所属公司）；
3. 最后在**岗位**页签建岗位。

> 已经存在在职员工或子部门的部门不能被删除，系统会提示"该部门下仍有在职员工"。
> 员工离职用「停用」而不是删除，历史考勤才查得到。

### 2.2 建立员工档案

菜单：「员工管理」

- 新建时**工号自动生成**（`LZ0001`、`LZ0002`…），也可手工指定，但必须唯一；
- 填错工号重复时，系统会直接提示"工号 xxx 已存在"；
- 「在职」改为「离职」后，该员工不再出现在各类下拉框里，但历史记录保留。

### 2.3 建立办公场所并绑定员工

菜单：「办公场所」

- 场所保存后会生成一个**场所码**；
- 经纬度支持**地图选址**：已接入高德地图（Key 由管理员在 `application-local.yml` 配置后生效），
  新建/编辑场所时可点「地图选址」打开地图抽屉，搜索地点 → 点击地图或拖拽标记取点，
  打卡半径以蓝色圆圈实时可视化，坐标确认后自动回填表单。
  **未配置地图 Key 时**入口自动隐藏，坐标回到手动填写——此时不做坐标自动选址；
  留空时围栏校验会在打卡时跳过（不会把空坐标当成"距离 0 米"而放行所有人）；
- 坐标存储统一为 WGS84（与手机浏览器定位一致），地图上的 GCJ-02 坐标由前端自动换算，无需关心坐标系差异；
- 「绑定员工」决定这名员工可以在这个场所打卡。

### 2.4 签发考勤二维码

菜单：「考勤二维码」

三种类型：

| 类型 | 适用 | 说明 |
|---|---|---|
| 动态码 | 日常考勤 | 有有效期，过期自动失效（后台任务每 5 分钟清理） |
| 长期码 | 固定场所长期张贴 | 可手动作废 |
| 一次性码 | 临时会议/外勤 | 用一次即失效 |

签发后页面会显示二维码图片，下方还有一个**「二维码原文」文本框 + 复制按钮**：
摄像头不可用时（比如用电脑浏览器演示），可以把这段原文粘贴到 H5 打卡页的手动输入框里。

> **关于安全**：二维码里不是数据库主键，而是"明文参数 + HMAC-SHA256 签名"。
> 二维码会被截图、转发、拍照，属于完全不可控的公开信道；只放一个自增 ID 意味着任何人把 ID 加 1 就能伪造另一个场所的码。

### 2.5 查看考勤与统计

- 「考勤记录查询」：按日期/部门/员工筛选；
- 「数据看板」：统计卡、趋势图、部门对比、出勤构成、场所时段分布五个图表。

**请注意看板上的数据源徽标**：

| 徽标 | 含义 |
|---|---|
| `real` | 全部来自真实打卡流水 |
| `mixed` | 混合了演示补录数据 |
| `sample` | 全部是演示补录数据，**不代表真实考勤** |

如果刚导入过演示数据、或看板数字看起来不对，点看板上的「**重新计算**」：
它会按实际流水区间重算日汇总，并立刻让缓存失效（不存在"点了没反应"）。

### 2.6 知识库

菜单：「知识库文档」/「智能问答」

- 支持 PDF、DOCX、XLSX、PPTX、DOC、XLS、PPT、TXT、MD 九种格式；
- 上传时可指定**可见范围**：公开 / 本部门 / 仅自己。普通员工检索不到无权查看的内容，
  这个过滤是在**数据库查询层**做的，不是查出来再丢掉；
- **已配置大模型（llm-augmented）**：答案由模型基于检索到的制度片段归纳生成，并附**来源出处**
  （文档名 + 页码/段落位置），便于核对；
- **未配置 Key 或生成服务瞬时不可用时，自动降级为原文检索（retrieval-only）**：有依据就给依据，
  没找到就明确说"未找到足够依据"，不会编造制度条款。

### 2.7 账号与角色

菜单：「账号管理」/「角色权限」

- 角色勾选权限后需保存生效，**权限是全量覆盖**（取消勾选即收回）；
- 删除角色前会检查是否还有账号在使用它。

## 3. 员工使用指南（移动端 H5）

### 3.1 打开打卡页

用手机浏览器访问 `/h5/checkin`（扫码或直接打开均可）。

页面会做三件事：

1. 请求定位权限 → 用于围栏校验；
2. 打开摄像头扫码；
3. **定位或摄像头不可用时，页面底部提供手动输入框兜底**，粘贴二维码原文即可打卡。

> 摄像头需要 HTTPS 或 `localhost` 环境；答辩演示时若用 `http://本机IP`，
> 摄像头可能被浏览器禁用，**用手动输入框兜底是完全正常的降级方式**，不是功能缺陷。

### 3.2 打卡结果与常见提示

| 提示 | 原因 | 怎么办 |
|---|---|---|
| 打卡成功 | — | 无需操作 |
| 重复打卡 | 5 分钟内已打过 | 等待窗口过去，或换班次场景 |
| 二维码已过期 / 已作废 | 码失效 | 找管理员重新签发 |
| 签名校验失败 | 二维码内容被改动过 | 不要手动修改二维码原文 |
| 不在该场所允许的范围内 | 超出围栏半径 | 走到场所附近重试；提示会显示实测距离 |
| 未绑定该场所 | 员工与该场所无绑定关系 | 找管理员在「办公场所」里绑定 |

### 3.3 人脸打卡（模拟通道）

`/h5/face` 提供人脸录入与核验，**这是明确标注的模拟实现**：

- 页面上标明了 `mock=true`；
- 服务端日志带 `[MOCK]` 前缀；
- **考勤以二维码打卡结果为准**，人脸只是核验通道。

真实虹软 SDK 需要商业授权，课程周期内无法获取；接入改造清单写在 `docs/face-sdk-integration.md`。

## 4. 常见问题

| 问题 | 处理 |
|---|---|
| 看板全是 0 | 日汇总没算：管理员点「重新计算」，或调用一次 `/api/statistics/daily-rebuild` |
| 刚上传的文档搜不到 | MySQL 5.7 的全文索引对刚插入的行有极短缓存合并时延，等 1~2 秒重试 |
| 手机打不开摄像头 | 需 HTTPS 或 localhost；否则用手动输入框 |
| 忘记演示账号口令 | `admin`/`Admin@123`、`manager01`/`Admin@123`、`emp01`/`Emp@123` |
| 数据看起来不真实 | 演示数据都带 `SAMPLE` 标记，接口返回里有 `dataSource` 字段区分，见 2.5 节徽标 |
