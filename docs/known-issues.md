## 3. 架构与环境限制

### 3.1 单体架构

当前是**模块化单体**（11 个 Maven 模块），不是微服务。这是权衡结果：
在这个体量下微服务带来的是运维复杂度和网络不可靠性，而非收益。
但模块边界已按"未来可拆分"的方式划定——业务模块之间**不编译依赖**，跨模块读表走 XXXSupportMapper 约定。

### 3.2 数据库版本

MySQL 5.7.19，**不支持窗口函数**，相关统计改为自连接/子查询实现。
另外 InnoDB 全文索引对刚插入的行有极短缓存合并时延：**连续上传文档后立刻检索可能偶发漏命中，等 1~2 秒重试即可**。

### 3.3 移动端摄像头

浏览器的 `getUserMedia` 要求 HTTPS 或 `localhost`。演示环境若用 `http://<本机IP>` 访问 H5，
摄像头会被浏览器禁用——此时页面底部提供**手动输入二维码原文的兜底通道**，这是设计好的降级方案。

### 3.4 Docker 磁盘

WSL2 后端的 `docker_data.vhdx` **只增不减**（删容器和镜像也不释放）。
本机已把磁盘映像迁到 D 盘（详见 `deployment.md` 3.0 节）。
若不迁移，长期构建会让 C 盘逐渐吃紧。

## 5. 演示数据说明

为让趋势图有内容、看板不空，系统内置了 14 天演示打卡流水（约 94~98 条），
全部带 `source='SAMPLE'` 标记、requestId 以 `SAMPLE-` 前缀开头。

- **可区分**：所有统计接口返回 `dataSource` 字段（`real` / `mixed` / `sample`）；
- **可清除**：按 `source='SAMPLE'` 一键删除即可回到纯真实数据状态；
- **不冒充**：界面上有徽标、接口里有字段，任何地方都不会把演示数据当真实考勤呈现。
